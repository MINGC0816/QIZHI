# 企知（enterprise_kb_agent）项目技术分析

> 文档版本：与代码同步整理（2026-08）  
> 项目路径：`enterprise_kb_agent/`  
> 定位：企业内部员工知识问答智能体（V1）— 本地文档 RAG + Agent + 内网大模型

---

## 1. 项目概述

### 1.1 要解决什么问题

将企业制度、规范、手册等本地文档建成可检索知识库，员工用自然语言提问，系统自动检索相关片段，再由大模型生成**有依据、可标注来源**的回答。

### 1.2 产品形态（V1）

| 入口 | 地址（默认） | 用户 |
|------|----------------|------|
| 员工问答 | http://127.0.0.1:3000 | 全员 |
| 知识库管理 | http://127.0.0.1:3000/admin | 管理员（当前无登录鉴权） |
| API / Swagger | http://127.0.0.1:8002/docs | 开发与联调 |

**V1 约束**：全员共用同一知识库，**不做权限隔离**；上传与向量入库分两步，需手动「重建索引」。

### 1.3 端到端主链路

```
┌─────────────┐    ┌──────────────┐    ┌─────────────┐    ┌──────────┐
│ 上传文档     │ →  │ data/raw 落盘 │ →  │ 重建索引     │ →  │ Chroma   │
│ (Admin 页)  │    │ (不 Embedding)│    │ 解析/分块/向量│    │ 向量库   │
└─────────────┘    └──────────────┘    └─────────────┘    └──────────┘
                                                              ↑
员工提问 ─→ Agent（工具调用）─→ search_knowledge / list_documents ─┘
                ↓
         内网 vLLM（Qwen）生成回答 +「来源：」
                ↓
         Sqlite 持久化会话（LangGraph Checkpoint + chat_threads）
```

要点：

1. **上传 ≠ 向量化**：上传只写 `data/raw/`；点击「重建索引」才跑 Embedding 并写入 Chroma。  
2. **问答不重新解析整库**：Agent 只对问题做检索，使用已入库向量。  
3. **LLM 不在本机**：对话模型走内网 OpenAI 兼容接口；本机只跑 Embedding（CPU）与业务服务。

## 3. 后端技术栈与用法

Python 要求：**≥ 3.11**。依赖声明见 `pyproject.toml`（版本多为下限，无 lock 钉死）。

### 3.1 Web 框架：FastAPI + Uvicorn + Pydantic

| 技术 | 用途 |
|------|------|
| **FastAPI** | 定义 REST API、依赖注入式路由、自动 OpenAPI |
| **Uvicorn** | ASGI 服务器；开发态 `--reload --reload-dir src` |
| **Pydantic** | 请求/响应模型校验（如 `ChatRequest`、`IngestRequest`） |
| **python-multipart** | `UploadFile` 表单上传 |
| **python-dotenv** | 加载 `.env` |

**具体用法（`src/api/main.py`）**：

- 应用生命周期：`lifespan` 记录启动/关闭日志。  
- CORS：仅允许本机前端 `3000` 端口。  
- 中间件：记录每个请求的方法、路径、状态码、耗时（`/health` 降为 debug）。  
- 管理端能力：上传、入库、原文预览、切片预览、删除文档。  
- 用户端能力：会话 CRUD、同步问答 `POST /api/v1/chat`。

默认监听：**127.0.0.1:8002**。

### 3.2 大模型接入：LangChain + OpenAI 兼容协议（vLLM）

| 技术 | 用途 |
|------|------|
| **langchain** / **langchain-openai** | 通过 `init_chat_model(..., model_provider="openai")` 对接兼容接口 |
| **内网 vLLM** | 承载 Qwen 等模型的推理与工具调用 |

**具体用法（`src/llm.py`）**：

```text
base_url  ← VLLM_BASE_URL   （如 http://10.60.40.130:12333/v1）
api_key   ← VLLM_API_KEY    （常为 EMPTY）
model     ← VLLM_MODEL      （如 Qwen3.5-VL-122B）
extra_body.chat_template_kwargs.enable_thinking ← VLLM_ENABLE_THINKING
```

温度默认 `0.2`，`max_tokens` 默认 `2048`。

**运维注意**：服务端需开启自动工具选择与对应 tool-call parser（如 `qwen3_xml`），否则 Agent 无法稳定调工具。

### 3.3 智能体：LangChain Agent + Tools + Prompt

| 技术 | 用途 |
|------|------|
| `langchain.agents.create_agent` | 组装「模型 + 工具 + 检查点 + 系统提示」 |
| `@tool` | 把检索函数暴露给模型调用 |
| **LangGraph SqliteSaver** | 按 `thread_id` 持久化对话消息图状态 |

**具体用法**：

| 文件 | 作用 |
|------|------|
| `src/agent/kb_agent.py` | `get_agent()` / `ask()` / 读历史 / 删会话元数据 |
| `src/agent/tools.py` | `search_knowledge`、`list_documents` |
| `src/agent/prompts.py` | 系统提示：先检索、禁编造、末尾标注「来源：」 |

问答流程：`ask(question, thread_id)` → `agent.invoke`（同步）→ 从返回消息中取最后一条有文本的 `AIMessage` → 更新会话标题/预览。

### 3.4 RAG 流水线

#### （1）文档加载 — `src/ingest/loaders.py`

| 格式 | 库 | 行为 |
|------|-----|------|
| PDF | **pypdf** | 按页 `extract_text`；无可提取文本则报错（多为扫描件） |
| Word | **python-docx** | 拼接段落文本 |
| MD / TXT | 标准库读 UTF-8 | 整文件一条文档 |

支持后缀：`.pdf` / `.docx` / `.md` / `.markdown` / `.txt`。

#### （2）分块 — `src/ingest/chunking.py`

- 库：`langchain-text-splitters` → `RecursiveCharacterTextSplitter`  
- 默认：`CHUNK_SIZE=700`，`CHUNK_OVERLAP=100`  
- 分隔符侧重中文：`\n\n`、`\n`、`。`、`；`、`，` 等  

入库时为每个切片写入元数据 `chunk_id`、`source`（文件名）、可选 `page`。

#### （3）向量化 — `src/rag/embeddings.py`

| 技术 | 用途 |
|------|------|
| **langchain-huggingface** | `HuggingFaceEmbeddings` 封装 |
| **sentence-transformers** | 实际加载/推理 Embedding 模型 |

配置：

- 模型：`EMBEDDING_MODEL_PATH`（默认项目内 `models/bge-small-zh-v1.5`，相对路径按项目根解析）  
- **设备固定 `cpu`**（故 `nvidia-smi` 上看不到属于预期）  
- `normalize_embeddings=True`，便于相似度比较  
- 权重目录约 90MB；Git 默认忽略 `models/**`（保留 `models/README.md`）

#### （4）向量库 — `src/rag/store.py`

| 技术 | 用途 |
|------|------|
| **ChromaDB** + **langchain-chroma** | 本地持久化向量检索 |

- 目录：`data/chroma/`  
- 集合名：`CHROMA_COLLECTION`（默认 `enterprise_kb`）  
- 能力：`add_documents`、按 `source` 删除、`list_sources`  

#### （5）检索 — `src/rag/retriever.py`

- `similarity_search(query, k=RETRIEVE_TOP_K)`，默认 **Top-K = 4**  
- `format_docs`：把命中片段格式化成带文件名/页码的上下文，供工具返回给 LLM  

#### （6）入库编排 — `src/ingest/pipeline.py`

`ingest_files`：加载 → 分块 →（`replace` 时先删旧向量）→ Embedding 写入 Chroma；失败按文件汇总到 `errors`，不中断整批。

命令行入口：`python scripts/ingest_folder.py`（可用 `--samples`）。

### 3.5 会话存储：SQLite 双层

| 层 | 技术 | 内容 |
|----|------|------|
| 对话内容 | `langgraph-checkpoint-sqlite` → `SqliteSaver` | 完整 message 轨迹 |
| 会话列表 | `src/sessions/store.py` → 表 `chat_threads` | title、preview、user_id、时间戳 |

二者共用 **`data/db/kb_agent.db`**。浏览器 `localStorage` 仅存当前 `thread_id`。

**局限**：删除会话目前只删元数据，不强制清理 checkpoint 行。

### 3.6 日志 — `src/logging_config.py`

| 输出 | 说明 |
|------|------|
| 控制台 | 同步 INFO+ |
| `data/logs/app.log` | 全量运行日志，5MB×5 滚动 |
| `data/logs/error.log` | 仅 ERROR+ |

级别由 `LOG_LEVEL` 控制。业务 logger 前缀：`qizhi` / `qizhi.api` / `qizhi.agent` / `qizhi.ingest`。

启动脚本另把 uvicorn 标准输出重定向到 `data/api.*.log`（与应用日志分开）。

## 4. 前端技术栈与用法

| 技术 | 版本（约） | 用途 |
|------|------------|------|
| **Next.js** | 15.1.0 | App Router、开发态 Turbopack |
| **React** | 19 | 组件与状态 |
| **TypeScript** | 5 | 类型约束 |
| **Ant Design** | 6.x | 按钮、上传、消息、布局主题 |
| **@ant-design/icons** | 6.x | 图标 |
| **@ant-design/nextjs-registry** | 1.x | 与 Next 集成，减少样式闪烁 |

### 4.1 页面与组件

| 路径 | 文件 | 功能 |
|------|------|------|
| `/` | `web/src/app/page.tsx` | 会话列表 + 对话主界面 |
| `/admin` | `web/src/app/admin/page.tsx` | 上传、重建索引、原文/切片预览、删除 |
| — | `ChatPanel.tsx` | 发消息、拉历史、展示回答 |
| — | `SessionSidebar.tsx` | 新建/切换/删除会话 |
| — | `web/src/lib/api.ts` | 封装所有后端调用 |
| — | `layout.tsx` | 全局主题（品牌绿 `#0B6E4F`）等 |

### 4.2 前后端如何通信

浏览器**不直连**后端端口，而是：

```text
浏览器 → http://127.0.0.1:3000/api-proxy/api/v1/...
       → Next.js rewrite（next.config.ts）
       → API_ORIGIN（默认 http://127.0.0.1:8002）/...
```

好处：开发期规避跨域；启动脚本会写入 `web/.env.local` 保证代理端口与后端一致。

## 5. 配置与数据

### 5.1 环境变量（`.env`）

| 变量 | 含义 | 典型默认 |
|------|------|----------|
| `VLLM_BASE_URL` | 内网推理服务 | `http://10.60.40.130:12333/v1` |
| `VLLM_API_KEY` | API Key | `EMPTY` |
| `VLLM_MODEL` | 模型名 | `Qwen3.5-VL-122B` |
| `VLLM_ENABLE_THINKING` | 是否开启思考链 | `false` |
| `EMBEDDING_MODEL_PATH` | Embedding 模型 | `models/bge-small-zh-v1.5`（项目内目录） |
| `RETRIEVE_TOP_K` | 检索条数 | `4` |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | 分块参数 | `700` / `100` |
| `CHROMA_COLLECTION` | 集合名 | `enterprise_kb` |
| `LOG_LEVEL` | 日志级别 | `INFO` |

### 5.2 持久化数据

| 目录/文件 | 内容 | 迁移注意 |
|-----------|------|----------|
| `data/raw/` | 原文 | 备份/挂载卷 |
| `data/chroma/` | 向量索引 | 与 Embedding 模型必须一致 |
| `data/db/kb_agent.db` | 会话 | 备份 |
| `data/logs/` | 运行日志 | 可清理 |

更换 Embedding 模型后，一般需要**清空 Chroma 并重建索引**，否则向量空间不一致会导致检索失效。

## 6. 启动与运行方式

| 脚本 | 平台 |
|------|------|
| `.\start.bat` / `.\start.ps1` | Windows |
| `./start.sh` | Linux / macOS |

启动行为摘要：

1. 定位虚拟环境 Python（优先仓库根 `.venv`）  
2. 必要时复制 `.env.example`、执行 `npm install`  
3. **启动前清理** `8002` / `3000` 上旧进程  
4. 后台启动 uvicorn（无额外窗口）  
5. 健康检查通过后前台启动 Next.js  
6. `Ctrl+C` 停止前后端并释放端口  

默认端口：**API 8002**，**Web 3000**。

依赖安装示例：

```bash
# 在 agent_study 仓库根
.\.venv\Scripts\pip install -e .\enterprise_kb_agent
```

## 8. 技术选型小结（为什么这样用）

| 选型 | 理由（结合本项目） |
|------|-------------------|
| FastAPI | 轻量、异步友好、自带 OpenAPI，适合快速搭 Agent 后端 |
| LangChain Agent | 用工具调用把「检索」从提示词拼装中解耦，便于扩展更多工具 |
| Chroma 本地库 | 零额外部署向量库，适合单机/内网试点 |
| bge-small-zh + CPU | 中文小模型、资源占用低；与远程大模型分工清晰 |
| vLLM OpenAI 协议 | 与业界客户端生态兼容，便于换模型不换业务代码 |
| Next.js + Ant Design | 管理端与对话端一体化，企业后台 UI 组件齐全 |
| SQLite Checkpoint | 单文件持久化多轮对话，部署简单 |

## 9. 当前局限与演进建议

### 9.1 已知局限

1. **无登录鉴权**，管理接口与问答接口对本机网络基本开放。  
2. **不支持扫描版 PDF**（无 OCR）。  
3. **Embedding 固定 CPU**，大批量入库偏慢。  
4. **上传与入库分离**，易出现「文件在、索引旧」。  
5. **问答同步阻塞**，无流式输出；长推理可能超时。  
6. **检索较简**：纯向量 Top-K，无重排 / 混合检索。  
7. **删会话不清 checkpoint**，库表会随时间膨胀。  
8. **强依赖内网 vLLM 与 VPN/专线连通性**。  

### 9.2 后续可演进方向（参考）

| 方向 | 说明 |
|------|------|
| Docker Compose | API + Web + data volume，便于上服务器 |
| OCR | 扫描 PDF 入库 |
| 鉴权与权限 | 登录、按部门/文档 ACL |
| 流式问答 | SSE / WebSocket |
| 检索增强 | 混合检索、Rerank、更大 Top-K 策略 |
| GPU Embedding | 配置 `device: cuda` 或独立 Embedding 服务 |
| 上传即入库 | 可选自动 ingest，减少人工步骤 |

## 10. 一句话总结

**企知**是一个「本地文档入库（pypdf/docx + 分块 + CPU Embedding + Chroma）+ LangChain Agent 工具检索 + 内网 vLLM 生成」的企业知识问答系统；前端用 Next.js/Ant Design 提供问答与管理界面，数据与会话落在本机文件与 SQLite 中，适合内网试点，并具备迁移到 Docker/服务器的清晰边界。
